# UX-004: icon family and SVG rendering review

Reviewed 2026-11-04 against Qt 6.12.0 Windows/Android kits and Tabler Icons
3.50.0, commit `6904efd245391ad396df17654738f52f6da8c40e`.
Application sources and dependencies have not been changed.

## Recommendation

**Keep the current Font Awesome font and icons.** In the native comparison,
their solid silhouettes and consistent Undo/Refresh arrow weight suit the small
icon sizes better. The user also prefers their rendering and appearance after
viewing the comparison. This is a visual judgment, not a measured recognition
study or a claim that every Font Awesome icon is superior.

The user initially selected Tabler filled where available, with outline Refresh
and Undo, and prefers VectorImage if SVGs are adopted. The later preference is
to stop pursuing Tabler. The experimental migration was stopped and all
production files were restored to the accepted Font Awesome implementation.
The experiment remains archived under ignored `out/ux004/`; no new SVGs,
renderer, color effect or Qt dependency remains in the app. The user accepted
the recommendation and requested ticket closure and commit on 2026-11-04.

Keeping the existing solution also follows KISS: it already supports the
palette, opacity and moving arrow feedback, while the tested VectorImage route
requires a tinting layer and additional native libraries. There is no concrete
rendering defect or functional gain here that justifies that cost.

Icon family and renderer are separate choices: Font Awesome also supplies SVGs.
Keeping Font Awesome's artwork while switching from a font to VectorImage is an
alternative if preserving the exact existing shapes matters more than adopting
Tabler. Merely changing the renderer does not require changing the artwork.

## Native visual and color probe

The comparison uses the real font and downloaded, pinned SVGs in the same
5.5 mm icon boxes, with Light and Dark foregrounds. Filled candidates retain
more of the existing visual weight; outlines are visibly lighter. Filled big
arrows are wider than the current arrows and need an in-context overlay check.
The image demonstrates rendering, not user recognition or phone readability.

![Native Font Awesome/Tabler comparison](../out/ux004/comparison.png)

Qt documents VectorImage as constructing a scalable Qt Quick scene, while Image
rasterizes SVG at a requested size. VectorImage exposes no direct color/tint
property in the installed 6.12 type metadata or documented API. SVG
`currentColor` does not inherit a QML Material palette automatically.
[VectorImage API](https://doc.qt.io/qt-6/qml-qtquick-vectorimage-vectorimage.html),
[Qt graphics approaches](https://doc.qt.io/qt-6/topics-graphics2d.html).

A native D3D11/WARP probe verifies a public-API approach: VectorImage with
CurveRenderer and a layer.effect MultiEffect using `brightness: 1`,
`colorization: 1` and `colorizationColor` bound to the owning icon color.
Brightness is needed for these black/currentColor source shapes: colorization
alone failed the white/accent pixel checks. This avoids private Controls types,
generated-child traversal and runtime SVG rewriting.
[MultiEffect API](https://doc.qt.io/qt-6/qml-qtquick-effects-multieffect.html).

Four probe records pass, including setup/cleanup: all outline/filled candidates
load and render in both palettes, and the cart passes live black/white,
green/red, alpha and two-size pixel checks. Larger glyphs establish fully
covered pixel colors; the saved comparison uses preview scale 1. The probe is
isolated under `out/ux004/`; it does not alter the app or its normal tests.
Layer tinting uses a texture pass: vector input alone does not establish better
performance. No Android rendering, full-list performance, pressed/disabled
control integration or cart-arrow animation migration is certified by this probe.

## Size and dependency tradeoff

The evaluated ten filled assets plus two outline assets total **6,207 bytes**,
before notices and resource packaging. Font removal saves 186,228 source bytes.
This does **not** imply a smaller APK.

An Android-kit QML scan plus ELF dependency closure adds eight native libraries
relative to the UI-024 APK: VectorImage/plugin, generator, helpers/plugin,
Effects/plugin and Qt Svg. Their installed binaries total **1,559,416 bytes**;
Quick Shapes is already shipped. Subtracting the font and adding the SVGs gives
an estimated **1.38 MB increase** before packaging/alignment and module resources.
This is an installed-kit inference, not a measured rebuilt APK delta.

Qt Svg is required by this VectorImage implementation even though no Image is
used. Keep unused SVG image-format/icon-engine plugins and Lottie excluded.
The current package test forbids Qt Svg, so migration must explicitly revise
that contract for the now-used dependency while retaining the other exclusions.

## Notices and maintenance

Tabler's pinned SVG set is MIT-licensed; ship its copyright and complete license
notice with the selected files. Use checked-in assets and a recorded upstream
commit, without a runtime download or npm/framework dependency.
[Pinned Tabler license](https://github.com/tabler/tabler-icons/blob/v3.50.0/LICENSE).

The matching Font Awesome release distinguishes fonts (SIL OFL 1.1) from SVG
artwork (CC BY 4.0). A Font Awesome SVG option would therefore change the
applicable asset notices rather than retain the font's license inventory.
[Font Awesome 5.7.2 license](https://github.com/FortAwesome/Font-Awesome/blob/5.7.2/LICENSE.txt).
The source formats and available filled/outline families are documented in
[Tabler's upstream project](https://github.com/tabler/tabler-icons/tree/v3.50.0).

## Conditional migration plan (not selected)

Retain this plan only for a future explicit decision to adopt SVGs. It is not
current application work. The accepted review settles UI-012's prerequisite;
About/licenses can use the existing Font Awesome font inventory.

1. Confirm the family/style mapping, particularly System, Undo and big-arrow
   overlays. Keep captions and accessible action meanings.
2. Bundle only the selected SVGs and MIT notice. Add one small decorative
   VectorImage-based source/color component, retaining each caller's ownership
   of actual dimensions and layout. Use the existing Material state colors,
   including UI-024's Undo foreground, disabled/pressed and highlighted states.
3. Adapt the current components and callers without changing gesture thresholds,
   timing or action delivery. Preserve separate cart and arrow layers, clipping,
   mirroring and animation ownership. Replace font padding with explicit optical
   geometry at the existing definition/caller points. Preserve IconButton's four
   display modes. Do not combine UI-017's deferred animation investigation here.
4. Remove the font, FontLoader and unused icon-font plumbing. Use meaningful
   asset URLs (including standard `icon.source` at button call sites), not glyph
   codepoints or a new icon registry/framework.
5. Add native-rendering tests for asset loading, bounds, live palette/state
   colors, alpha, resizing and composed arrow feedback. Retain swipe, Undo,
   drawer-caption/display-mode and real-button interaction coverage. Keep bug
   fixes separate with failing-before/passing-after regressions if discovered.
6. Build both Android ABIs, update and run package/dependency checks, and measure
   the actual APK change. Check Android gestures, arrow feedback, Undo, themes,
   safe-area/IME placement and long-list performance using isolated data. Run
   normal Windows verification and qmlformat before acceptance.
7. Finalize the icon/font and newly used Qt-module inventory for UI-012 and
   REL-001 after the chosen migration is accepted.

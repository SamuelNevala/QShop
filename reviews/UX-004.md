# UX-004: Font Awesome or Tabler

**Resolved 4 November 2026: keep Font Awesome.** The user preferred its rendering
in the native comparison. Solid silhouettes and consistent Undo/Refresh weight
fit the small icons; there was no demonstrated benefit to justify migration.
Production sources/dependencies were restored; experiments remain in out/ux004.
The later Font Awesome update is separate from this review's 5.7.2 baseline.

## Evaluated option

Tabler 3.50.0, commit 6904efd245391ad396df17654738f52f6da8c40e: filled where
available, outline Refresh/Undo. This was a visual comparison, not a recognition
study. Definitions/callers included TextIcon, Icon/Button, arrow/cart/bin,
chooser, editor, pulley, delegates, ShopView, View and UndoBar. Callers must retain
actual bounds; SVG canvas size alone does not preserve optical geometry.

VectorImage is the preferred SVG renderer if reconsidered. In Qt 6.12 it lacks a
direct tint property; SVG currentColor does not inherit Material automatically.
A CurveRenderer plus MultiEffect layer passed live palette/alpha/size pixel tests
using brightness=1, colorization=1 and the owning color. That layer costs a texture
pass. Four native D3D11 WARP probe records passed; no Android animation/performance
or full control-state migration was certified.

## Size and licence tradeoffs at that baseline

- Twelve SVGs: 6,207 source bytes versus the then-font's 186,228 bytes.
- Android QML/ELF closure added eight native libraries, 1,559,416 installed bytes;
  estimated net increase about 1.38 MB before packaging, **not a measured APK delta**.
- Tabler assets are MIT; Font Awesome font is OFL, its SVGs CC BY 4.0. Changing
  renderer/asset format requires the corresponding notices. Icon family and
  renderer are independent choices.

If selected later: pin checked-in assets/notices; preserve glyph geometry,
four button display modes, enabled/pressed colors, arrow layers and gestures;
add native loading/palette/alpha tests, then rebuild both Android ABIs and measure
the package. No migration is currently selected. About/licenses can use the
retained font; later logo VectorImages are a separate dependency decision.

# UX-002: swipe colors and color vision

Reviewed 6 November 2026 against d944dc9; accepted 7 November. **Keep red for
delete and green for check/uncheck, with the existing cart/bin, arrow and state
cues.** UI-028 separately fixed Light-theme foreground contrast. No extra color
picker or color-blind theme was needed.

Android recommends consistent meanings, sufficient contrast and cues beyond
color. A different hue pair alone would not solve color-vision accessibility.
Use 3:1 for meaningful graphical cues against their actual composed background;
this is a review target, not whole-app accessibility certification.

## Evidence and limits

The native Windows software probe rendered 32 settled states using production
feedback components. [Measurements](UX-002/measurements.json),
[simulation colors](UX-002/simulation-colors.json), [comparison](UX-002/comparison.png),
[probe](UX-002/tst_actioncolors.qml) and [analysis](UX-002/analyze_frames.py)
retain the baseline. Offline simulations are illustrations, not Android captures
or recognition studies. Light icons exposed the contrast defect fixed in
[UI-028](../tickets/UI-028.json), with actual-touch before/after regressions.

The old synthetic probe aborted under D3D11 WARP with an opacity assertion;
temporary clamping did not resolve it. Its cause remains unexplained and was
not established as an app bug. The separate production-touch regression passed
native WARP. No APK rebuild/full suite was claimed for the review-only baseline.

Android user color correction and developer Simulate color space are different.
Android documents that simulator screenshots retain normal colors; an ordinary
ADB screenshot cannot certify the live simulated display. Observe the live output
or a validated final-display capture, then restore the setting. Outdoor use,
actual color-vision recognition and reduced-motion behavior remain separate checks.

## Repeat the baseline probe

Build the normal Windows tests, use the software backend and run
reviews/UX-002/tst_actioncolors.qml with qshopper_ui_tests. Run
`python reviews/UX-002/analyze_frames.py` with NumPy/Pillow. Full working-directory
commands and diagnostic attempts remain in `git show 73ada02:reviews/UX-002.md`.

# DEV-001: Qt Virtual Keyboard property-override diagnostic

Investigated 2026-11-07 with Qt 6.12.0 MSVC x64. Outcome: upstream-owned
diagnostic; no application change required. The warning remains visible.

## Origin

The exact application diagnostic is:

```text
qt.qml.propertyCache.append: Member contentWidth of the object PopupList_QMLTYPE_... overrides a member of the base object. Consider renaming it or adding final or override specifier
```

The installed Qt file
`C:/Qt/6.12.0/msvc2022_64/qml/QtQuick/VirtualKeyboard/Components/PopupList.qml:10`
declares `readonly property real contentWidth: contentItem.childrenRect.width`
on a ListView. QShopper has no PopupList component or copy of that declaration.

In this SDK, `qquickflickable_p.h` declares the inherited contentWidth property
VIRTUAL. `qqmlpropertycache_p.h` identifies this message as
MissingOverrideOrFinalSpecifier and permits that override for Qt 6 backward
compatibility. This differs from an ignored override of a FINAL property.
The SDK files were inspected, not modified.

## Independent reproduction

`tests/upstream/tst_virtualkeyboard.qml` runs with Qt's own qmltestrunner and
imports only Qt modules. It does not load QShopper, its C++ setup or application
QML. Its direct-source case loads the original installed PopupList file with an
empty model and overrides its delegate/highlight/add/remove bindings to remove
the enclosing keyboard context dependency. The same warning is emitted and
the inherited/derived width remains usable. Its InputPanel control uses actual
virtual keys and checks committed text and show/hide state.

For the validated kit, from the checkout:

```powershell
$env:PATH = 'C:/Qt/6.12.0/msvc2022_64/bin;' + $env:PATH
$env:QT_IM_MODULE = 'qtvirtualkeyboard'
$env:QT_VIRTUALKEYBOARD_DESKTOP_DISABLE = '1'
$env:QT_QUICK_BACKEND = 'software'
New-Item -ItemType Directory -Force out/dev001 | Out-Null
& C:/Qt/6.12.0/msvc2022_64/bin/qmltestrunner.exe -input tests/upstream -platform windows -o out/dev001/qt-only.txt,txt
```

The explicit source URL in this optional fixture intentionally identifies the
validated SDK. Adjust it and the command together for another kit. This is not a
normal CTest entry that requires every future Qt release to emit an old warning.

The usual Qt module import prefers its embedded compiled resources. A standalone
InputPanel import alone was quiet; explicit parsing of the installed source
reproduces the diagnostic. Thus emission depends on the loading path. The
independent source reproduction establishes ownership; it does not claim the
entire production cache/import trigger has been minimized to one setting.

## Behavior and limits

- Qt-only Release and Debug runners: four records pass, with the exact warning
  in the direct-source case. Final durable fixture:
  `out/remaining/qt-only-final.txt` (Release Qt qmltestrunner).
- Current production `qshopper_keyboard_tests`: six records pass, including
  actual virtual keys/Return, composed input, hide/reopen, preview resize/zoom,
  drawer dismissal and Back. Its report still contains the warning.
- No failing app behavior, ignored final property, or broken data was found by
  these checks. They do not certify every Qt language/candidate popup interaction.
- Android uses the native system IME and does not ship this desktop keyboard
  module. The ordinary desktop AUTO build gate remains unchanged.

Do not patch the installed SDK, vendor a keyboard component, rename an app
property unrelated to the source, or globally suppress QML warnings. Recheck the
optional repro and real keyboard controls on a Qt upgrade. No public upstream
issue number was established; no external report was submitted.

# QA-002: display, physical sizing and readable text

Status: native simulation matrix plus pending physical validation. There is no
reported sizing defect. No application or density-formula change is implied.

## Native simulation

`tests/android/test_displaymatrix.py` runs the existing text-fitting and selector
endpoint/cold-restart tests at these isolated emulator configurations:

| Profile | Requested resolution | Logical density | Purpose |
| --- | --- | --- | --- |
| Baseline | 1440 × 3120 | 560 | Existing AVD |
| Compact | 1080 × 1920 | 480 | Narrower, shorter phone viewport |
| Roomy | 1440 × 3120 | 420 | More logical space without crossing the large-display threshold |

The runner stores device/IME/font-scale metadata, `wm` values, display/window
dumps, real screenshots, row bounds and child results. It attempts the original
size/density and rotation restorations in `finally`, records restoration errors
and verifies the restored values match. A disconnected emulator fails validation;
software cannot certify restoration while its transport is unavailable.

These profiles establish actual native rendering, short/long text fitting,
retained source text, safe popup bounds, reachable options and cold selection
restoration under simulated geometry. Logical density overrides do not create
independently calibrated physical displays or another device's graphics/IME.

Final results on 2026-11-07: all three profiles pass 20 text and 26 selector
records each (138 total), with both-theme screenshot dimensions and effective
wm values checked. All final restorations match. The three reports are
`out/remaining/android-displaymatrix-baseline-final/results.json`,
`android-displaymatrix-compact-verified/results.json` and
`android-displaymatrix-roomy-verified/results.json`. They identify the same
installed APK hash; `out/remaining/verification-summary.json` consolidates the
current pass. These results do not complete the physical record below.

## Compact navigation setup observation

The original immediate-release `input swipe` setup passed baseline and most
compact cases, but twice did not enter editing at compact size. One failure was
after restart; a later initial-entry failure persisted through bounded polling.
Those failures occurred before the relevant selector assertion, not as a
demonstrated selection/persistence defect. Reports remain under
`out/remaining/android-displaymatrix` and
`out/remaining/android-displaymatrix-compact-final`.

Three fresh compact held-frame controls used the same coordinates and requested
1200 ms movement. Each visibly armed the green pulley and entered editing after
release (`out/remaining/compact-pull-probe`). Their capture-controlled hold was
longer than the final setup's hold, so it is a separate diagnostic control.

The selector driver now uses one continuous helper gesture with requested
1200 ms movement and exactly 200 ms at the final point, then awaits the editor.
It never retries a gesture or calls the model to bypass navigation. The complete
compact text/popup matrix passes with this exact setup in
`out/remaining/android-displaymatrix-compact-verified`: 20 text and 26 selector
records. The cause of the original immediate-release variability was not proved;
no app bug or threshold fix is claimed. Immediate-release/rejected pulls retain
their separate tests, and physical comfort on shorter displays remains pending.

An intervening run had no initial Android accessibility root and failed before
any gesture. Bounded startup-root polling was added; no app crash appeared in
the captured log. Each of those earlier compact runs restored its display overrides.

A subsequent baseline run lost the emulator itself after its host logs recorded
graphics-context/external-memory failures. ADB disconnected, so restoration
commands could not run. This is an invalid environment run, not a passing matrix.
Its logs remain in `out/remaining/android-displaymatrix-baseline-verified` and
`out/remaining/emulator*.log`. The task-owned emulator was restarted, and its
recorded 1440×3120/560, rotation 0/auto-enabled settings were reconciled before
continuing. The runner now records cleanup errors while attempting every
restoration; it cannot hide a lost transport as success.

`tests/android/test_displaymatrix_control.py` reproduces that controller boundary
offline. It fails against the earlier controller snapshot and passes after
restoration errors are captured and persisted (`out/remaining/matrix-control-before.txt`
and `matrix-control-after.txt`). This is a controller regression, not an app fix.

## Physical record

### Connected Windows displays (2026-11-07)

The production app was opened on both connected monitors with native Windows
rendering (D3D11 WARP). Both themes and preview scales 1 and 2 pass; moving an
existing window twice between the monitors at scale 1.5 preserves item
identities/order/checks, the editor draft and the open desktop keyboard.
Actual captured glyph pixels, fitting bounds, the three-line cap, large short
text and checked styling are checked in each case.

| Monitor | Qt logical size | DPR | Reported logical px/mm | Debug density correction |
| --- | --- | --- | --- | --- |
| LG TV SSCR2 | 3840 × 2160 | 1 | 2.4 | 1.5 (existing TV workaround) |
| LG ULTRAFINE | 3072 × 1728 | 1.25 | 5.10117647 | 1 |

`tests/displays/tst_displays.qml` provides repeatable, opt-in hardware coverage.
The sibling screen observer verifies the same owning window as Theme; captured
render-target dimensions must follow the current monitor's DPR. Production
density calculations remain unchanged. Native Windows may report transient
geometry adjustments while crossing monitors; settled dimensions must match
the reference window size. Reports/screenshots are in `out/displays`.

The monitors' EDID reports 160 × 90 cm for the TV and 60 × 34 cm for UltraFine.
These are device metadata, not ruler measurements. In particular, the TV has an
existing correction for inaccurate metadata. This run establishes actual
monitor rendering and transitions; the ruler/comfort fields below remain open.

The nominal font size is not the visible glyph-ink height. Measure row geometry,
not the black/white part of a letter. Do not invent a numeric acceptance tolerance:
report the measured deviation and usability result for the user to assess.

`Theme` uses the owning window's reported `Screen.pixelDensity`; Android preview
scale is always 1, with no devicePixelRatio multiplication/division. An emulator
matrix cannot verify that a particular manufacturer's physical-density metadata
is accurate. Record a mismatch before proposing a targeted correction.

## 3. ArrowIcon.qml — reviewed, validation candidate recorded

### Definition and caller responsibilities

[ArrowIcon.qml](../app/ArrowIcon.qml) extends TextIcon with a clipped, animated child
glyph. Keep the shared implementation: it serves three small derived variants
without duplicating their state/animation machinery.

- The root receives actual bounds from its caller. Its nested arrow uses 35% of
  root height, full root width and proportional padding. The parent font family
  flows to the child. Animation writes child y; it does not compete with a layout
  for root dimensions. No fixed implicit size or layout wrapper is needed here.
- `arrow` and `animation` are intentional object-alias extension points. CartInIcon
  changes the destination and padding; CartOutIcon also changes the start,
  easing and arrow glyph; TrashIcon changes its glyph and destination. The aliases
  keep these small definitions direct. Extra forwarding properties would not
  improve the current use sites.
- `ratio` comes from displacement divided by allocated icon width in TextDelegate,
  with the sign reversed on the mirrored side. It starts animation above 1 and
  rearms at exactly 0. This is decorative feedback after roughly one icon width
  of movement, separate from SwipeHandler's velocity/half-row action decision.
  ArrowIcon itself emits no selection/delete action and does not mutate the model.
- The custom `animated` flag records that the arrow already ran during this
  excursion. It deliberately stays true after the animation completes until ratio
  reaches 0. Using only `running` would allow repeated animation in the same drag.

### Instantiation trace

| Definition / use | Customization and allocation |
| --- | --- |
| [CartInIcon.qml](../app/CartInIcon.qml) | Cart body, downward arrow, cart-specific padding and destination |
| [CartOutIcon.qml](../app/CartOutIcon.qml) | Cart body, upward arrow, reversed endpoints and InBack easing |
| [TrashIcon.qml](../app/TrashIcon.qml) | Trash body with a different arrow destination |

| [TextDelegate.qml:183](../app/TextDelegate.qml#L183) and :192 | Right IconChoser selects CartOut or CartIn; same square allocation with mirrored visual transform and signed ratio |

The two IconChoser Loaders size their loaded variant to the square allocation;

Its default body glyph is inherited fallback, not an additional live UI control.
Derived variants and IconChoser were read as callers/dependencies; their own
reviews remain pending. Existing color roles remain for the separate UX reviews.

### Lifecycle observations

A native Windows component probe loaded all three variants through the production
IconChoser, with the bundled font and Theme.pixels(9.27) allocation. Normal cycles
behave consistently: ratio 1 does not start, ratio above 1 starts once, subsequent
above-threshold changes do not retrigger after completion, and returning to 0
allows a later settled cycle to start again. Geometry follows the Loader.

Two additional observations need real user-path validation before declaring a
visual bug:

1. Returning ratio to 0 during the 800 ms animation clears the latch and sets y
   to from, but leaves the animation running. Its next frames move the arrow
   again. Crossing above 1 immediately afterward calls start on that still-running
   animation, so only the original start is observed. Whether finishing the old
   feedback is desirable must be checked in the rendered pullback/repeat path;
   alwaysRunToEnd is explicitly enabled in this component.
2. After a completed cycle and reset, doubling the allocation updates the
   animation endpoints but leaves idle y at its old value. For example, CartOut
   stays at about 8.343 px while its new from is about 16.686 px. The reset's
   imperative assignment replaces the y binding. The production caller has zero
   target opacity at rest, so a stale internal coordinate alone does not establish
   a visible user failure on the next gesture.

with severity unassigned. No fix, severity escalation or unrelated UI-015
investigation is selected by this review. A future fix must first reproduce the
undesired rendered behavior and add a permanent failing-before/passing-after
regression for that trigger.

## 8. IconChoser.qml — reviewed, no changes needed

[IconChoser.qml](../app/IconChoser.qml) is a small Loader specialization with two
state inputs and three Component inputs. Its single sourceComponent binding
states the priority directly: edit mode selects trash; otherwise checked selects
cart-out; otherwise cart-in. Keep that binding and the Component inputs. Extra
states, a selection function, an enum framework or three permanently allocated
hidden icons would add machinery without making the current uses clearer.

Both production instantiations were traced:

- [TextDelegate.qml:117](../app/TextDelegate.qml#L117), left side: checked and editMode
  follow the row. All three variants are supplied, so the edit-mode branch takes
  precedence for both checked and unchecked rows. Top/bottom anchors establish
  the chooser's height, width follows height, and the left anchor positions it.
- [TextDelegate.qml:177](../app/TextDelegate.qml#L177), right side: checked follows the
  row, editMode stays at its false default, and only cart-in/cart-out are supplied.
  The optional trash component is therefore never selected by this caller. The
  square allocation follows the same vertical anchors/width binding and the
  whole chooser is mirrored horizontally. Do not propagate editMode here merely
  to make the declarations symmetrical; this side retains its existing
  check/uncheck feedback instead of deletion feedback.

The icon components' ratio, opacity, font and theme bindings remain at the caller,
where the row state is known. Loader owns the selected object's geometry inside
the allocated square. The chooser needs no fixed implicit row size, internal
anchors, extra Item wrapper or Layout hints; neither caller is directly managed
by a Qt Quick Layout at this point.

Loader also owns creation/replacement of its selected item. A sourceComponent
change destroys the old loaded object; it does not require explicit destroy calls
or a second cache. If editMode remains true on the left, changing checked still
selects the same trash Component, so the binding does not intentionally request
an unrelated icon. No production consumer of these callers assumes a particular
loaded icon before selection. The public interface does not need a mandatory
trash component, a speculative null fallback or a visibility-driven recreation
policy for the two supported use sites.

Tracked searches found these two instantiations, module registration and no
subclass or additional dynamic creation path. Existing native ArrowIcon probes
already instantiate variants through IconChoser, and the latest DEV-009 full
Windows run passes 247 records after WheelIcon removal. Those results are reused;
no new runtime test or application/tracked-test change was made for this source
review. They are supporting coverage, not an exhaustive assertion of every
chooser state combination or Android rendered interaction. UI-017 remains a

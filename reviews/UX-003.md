# UX-003 — Custom primary/accent roles

Review and implementation selected 2026-11-07 against `c632dd3`, Qt 6.12.0.
The user authorized completing the work unattended, including confirmed fixes,
and separately selected UX-005. These are independent changes. Automated verification is complete. The user tested the APK and accepted the
review and fixes on 2026-11-07, requesting closure and commits.

Keep the existing color roles, all 19 families, System/Light/Dark, vivid shade
selection and neutral surfaces. A custom component using Material attached
colors is a sensible use of Qt's palette. No component replacement, additional
picker or general token framework is needed. The defects concern colored ink
and a thumb boundary, rather than the choice of global primary/accent families.

## Confirmed findings and corrections

[UI-029](../tickets/UI-029.json) covers colored name/tab/icon/focus ink and the
drawer surface context. Native Windows held-press/render checks fail before:
Light Yellow day name 1.198:1, armed pulley 1.211:1,
focused ComboBox 1.236:1; Dark Purple pressed editor icon 2.031:1. The original
drawer reports background #fffbfe to children while painting #d1d1d1 in Light.
The final Layout-preserving selected-tab regression fails at 1.203:1 against
the original AboutDialog under offscreen/software with Windows fonts. Its early
logo-reflow pilot is excluded. Real Android held pulls independently reproduce
faint Yellow names/pull glyphs.

`Theme.readableInk(ink, surface, opacity, minimum)` retains an already-readable
color and otherwise tints toward a contrasting neutral. For 80% neutral surfaces
it checks the conservative photographic extreme: black behind Light, white
behind Dark. Small labels target 4.5:1; meaningful icons/focus cues target 3:1,
with a 0.1 margin for rendered-color rounding. It does not change palette ramps
or filled-control foreground policies.

[UI-030](../tickets/UI-030.json) covers the thumb edge: native Windows Yellow
1.236:1 and Android 1.238:1 before. A 0.2 mm normal neutral outline identifies the
thumb while its fill/active track remain vivid. Existing keyboard focus uses
0.4 mm. A track is not required to carry the entire value cue when the thumb
boundary and numeric percentage do so.

## Verification and limits

Permanent `tests/customcolors/tst_customcolors.qml` exercises all 19 families in
Light/Dark plus native Windows System cases. It checks actual rendered glyphs,
both black/white photographic extremes, real editor presses, focused borders,
actual drawer propagation, both selected license tabs and the thumb boundary.
The controls persist through palette/theme changes; this tests live bindings.
It runs in normal offscreen/software and native D3D11 WARP CTest entries.

`tests/android/test_customcolors.py` uses disposable data, actual held pulls and
pressed editor controls, slider pixels and both license tabs. It captures opaque
ink against adjacent neutral pixels in the same frame, avoiding moving-photo
reference races. Before captures and logs are under `out/ux003/`.
Final results: all 17 Windows suites pass (1,622 records), including 268
offscreen and 282 native custom-color records. All 283 native Android checks
pass (48 custom-color, 6 cleanup, 24 recovery, 26 About, 42 popup and 137
System drawer/safe-area checks). Both APK package/signature checks pass. All
67 QML/templates and 11 C++ files pass formatter Check; both C++ analyzers pass
all seven translation units. QML lint exits zero with five existing warnings
listed in the tickets. Full command/log details and original-source negative
controls are retained there.

Rendered RGB checks do not establish outdoor readability, recognition by users
with color-vision differences, or Android's live correction/simulator output.
Those limits do not justify another color picker or replacing working components.

## Guidance used

Qt documents that Material theme/primary/accent/foreground/background propagate
to children. Supplying the painted drawer surface through that property is the
appropriate local correction. The installed Qt 6.12 Material and Fusion QML
sources were checked for inherited tab backgrounds, label and selection roles.
[Qt Material style](https://doc.qt.io/qt-6/qtquickcontrols-material.html).

Android recommends consistent semantic roles and checking foreground/container
tone pairings while allowing expressive static palettes. Keep UX-001/002's
accepted choices and correct individual pairings.
[Android color guidance](https://developer.android.com/design/ui/mobile/guides/styles/color).

The review uses 4.5:1 for small text and 3:1 for meaningful graphical/state cues,
after composition. Decorative borders, inactive controls and unused hypothetical
variants are not blanket reasons to recolor the app. These are review targets,
not whole-app accessibility certification.
[Text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html),
[non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

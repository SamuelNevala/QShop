# UX-005: Undo cleanup actions separately

**Resolved and user-accepted 7 November 2026.** After Reset, users remove
non-recurring items; restoring the entire deletion batch also revived intentional
removals. Undo now restores the **latest action**, with further taps recovering
earlier actions. One Remove checked/Clear list action remains one coherent step.

For example, delete candles, gift wrap, then Milk by mistake: one Undo returns
only Milk; subsequent taps deliberately restore gift wrap, then candles. Keep
identities, flags, order, pending editor work and neighboring new entries.

## Implementation and current timing

Remove UndoRemove's command merging and use existing QUndoStack semantics; no
new history engine, screen, extra button or persistent recovery archive.
New deletion after Undo discards the undone future, preserving older pending steps.
Expiry clears all pending recovery; restoring the last step hides the bar.
Drawer/inactive pauses and list/reload/process boundaries remain unchanged.

The initial implementation retained one shared 15-second deadline. **UI-032 later
superseded that timing:** exposing an earlier action through Undo gives it a fresh
15 seconds. Each new deletion also restarts the window. Use current
[DESIGN.md](../DESIGN.md) and [UI-032](../tickets/UI-032.json), not the original
shared-deadline rule, for further changes.

## Before/after evidence

Four new model cases failed originally (individual post-reset recovery,
deletion after Undo, separate Remove checked/Clear steps). Actual QML swipes
exposed the merged count. Android cleanup returned all original rows after one
tap instead of only the mistaken removal. These became passing permanent
regressions; [UX-005](../tickets/UX-005.json) retains exact tests/logs.

At acceptance: 104 model records, 17 combined Windows suites/1,622 records,
six Android cleanup checks and 24 native recovery checks passed. Recovery covers
offscreen editor, scroll, separate taps, Gboard retention, expiry/background pause
and cold persistence. Both analyzers and APK package/signature checks passed.

An intermediate idle UI dump stalled during the animated countdown; final native
tests locate the bar from rendered frames. Automation did not use the physical
microphone or install on a phone. Later user acceptance does not fill every
broader natural-dictation/physical QA field.
